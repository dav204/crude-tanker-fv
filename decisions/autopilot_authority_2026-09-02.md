## 0. TL;DR

1. **What changes for you:** the daily digest becomes subject-only; you get one Saturday email with a verdict subject line, a decision queue with one-word slots, and a health table. Pages are reserved for a fixed set of events (§4.2 routing table).
2. **What the machine does alone, once ratified:** absorbs the nightly price vintage and ratifies price-only drift; promotes the dry FFA curve when a print passes a coded predicate; applies issuer-sourced earnings-date confirmations; advances test pins inside their bands; re-runs sidecars, rebuilds the Pareto manifest, flushes drift files; lands a report-day pair you already committed when it hits its frozen band (Stage C). Every landing leaves a decision doc, a branch, a commit under a distinct `crude-fv autopilot` git identity, an `AUTOPILOT_LOG.md` row and — where a ratify occurred — a `RATIFY_LOG.md` row.
3. **What stays yours:** every fork/WO/tier/weight ruling, every non-standard S&P print (auction, unnamed, aggregate, cross-house conflict), every flip toward BUY, every band miss, report-day extraction judgment, `git push origin main`, `PLAN.md`, outward contacts, IBKR.
4. **The actor is code, not an LLM.** `crude_tanker_fv.promote` is a Python module run by launchd in a worktree *outside* the repo; it lands only by `git merge --ff-only`. Agents (desktop scheduled tasks) keep the 2026-07-03 zero-authority category and only write drafts into a gitignored candidate directory. No `claude` CLI install for Stages 0–C. **No `.claude/settings.json` widening**; Stage A carries three *narrowings* and one read-only CLI allow, listed in §6 — note the narrowing of `twelve_month_tc.yaml`/`spot_tce.yaml` from allow to ask will prompt you during your own interactive FFA promotes.
5. **Why not an unattended agent:** `PERMISSIONS_PROPOSAL.md` §6 Q4 — autonomous sessions auto-approve ask-tier; only deny gates. And 216/216 commits since 7/20 carry your git identity (208 with the Claude trailer), so "author == owner" proves nothing (§4.3).
6. **The answer channel:** your word in a session, as today, executed immediately and stamped into `decisions/owner_queue.md` by a CLI verb; an unattended file-commit path exists for when you are away, guarded by a per-report nonce (dead in an SMTP-outage week — in-session only then).
7. **Silence is safe:** an unanswered item never expands authority; staged sets hold and re-cut at 21d; a held ratify pages only when it blocks a dated event.
8. **Honest minutes:** the three verifiers put in-season attention at **2.5–6.6 h/wk** today (the spread is the measurement, not the design). Stage B removes the mechanical half (ratify commands, drift flushes, regen babysitting, pin advances, page reading: ≈60–90 min/wk); Stage C removes the landing half of refreshes. Report-day *judgment* and rulings are untouched by design (§9). Outage-week price salvage is **not** removed — it becomes optional (§1.2 #5).
9. **Delivery calendar, from the stage gates as written** (Stage 0 one sitting → 1-week clean gate → Stage A two Saturdays → Stage B → 4-Saturday season → Stage C):
   - Noise fix (20 pages/month → a handful), sentinel-crash visibility, `REAUTH-NEEDED` page, manifest indexer in the daily chain: **Stage 0 — this week.**
   - Weekly report + decision queue + `SEAM-ENTER` ("something to buy") page: **Stage A — 9/19 earliest** (9/12 only if Stage 0 lands 9/02 and the gate week is 9/02–9/09). Until then a new edge-cleared name is learned only by reading the Verdict.
   - FFA promoted unattended: **Stage B — ~10/03 earliest**, then Q-5's default freezes lane B from 10/01 until the strip roll is ruled as its own event. Realistically the first unattended FFA promote is **mid-October**; each month-end/straddle print stays STAGE unless Q-2 rules yes.
   - S&P prints: **a one-word Saturday act in October (Stage B); plain rows unattended only at Stage C (~early November), and only for rows the dedupe, lexicon and deal-structure predicates clear.** Pareto-only rows are not excluded by design (item 7 in Appendix A), but the round's judgment rows stay yours.
   - "Run every week without me": Stage C at the earliest (November); report-day judgment never leaves you (§8).
   - **Nothing in this document changes the 9/03–9/05 sequence** (CMBT 9/03 → Stage B window 9/04 → R4 9/04–05, PLAN.md L47–64) — those are handled exactly as today.
10. **Nothing in Stage 0 needs a ruling beyond "adopt"** — bug fixes with guards plus compiling the WO2 acceptance season the repo set as its own precondition. **To start:** rule Stage 0 "adopt", then the pre-Stage-B forks in §10 (Q-0…Q-5 and Q-12 — one word each; all have a recommendation).

### 3.3 Bounded ratify and the annotation loophole

`drift_gate.decision_log_annotated_since` treats *any* newest header not starting "pipeline run (auto)" as human — a machine writing `## <date> [autopilot]` would bless `band-EXIT`/`k_broker` rows. The promoter therefore **never writes into `decisions/<t>_log.md`** beyond the pipeline's own auto-prepend, and a guard asserts no commit by the autopilot identity ever changes a non-placeholder `**Decision:**` line `[N]`. The **one** machine-readable explanation it may rely on is the owner-committed `decisions/predicted/<t>_<q>.yaml` band (lane 6, Stage C) — human provenance, machine evaluation. Its explanation of record otherwise is the comparator table in its decision doc; its re-anchor is `scripts/ratify_baseline.sh "<cause>"` (the ONLY sanctioned path; the script does not commit) invoked iff every forcing row has breaches ⊆ {EV%} and lies inside the lane's frozen band, zero band-EXIT, zero BUY-ward, zero k breaches. Ordering: comparator → ratify → suite.

Auto-prepends bury owner annotations (only the top entry counts). Rows explained at the branch base by an owner annotation but not ratified become UNEXPLAINED after the promoter's regen → `RATIFY-OWED (owner)` refusal, visible in the queue. This matches practice since 8/13 (annotate and ratify in the same sitting). A two-cause attribution run (rules-reader D6) is deliberately not machine work (Appendix A).

`promote rollback <run-id>`: refuses unless main HEAD == that run's landing commit; `git revert --no-edit` the range; restore the pre-run `state/` snapshot; append a `rollback of <run-id>` RATIFY_LOG row if the run ratified; write `state/autopilot/PAUSE`; page once.

`id` = `sha256(lane, candidate key, rec text)[:8]`; a ruling binds to the id and to the staged file's content hash (the draft is gitignored, so the hash — not git — is the binding). `RULING: accept recs W37` at the top answers every item whose `rec:` is a legal answer, scoped to that report id.

**Channel A (recommended, primary): the word in a session.** You say "accept", "rule B", "run the round" — the session executes as today and records it with `promote rule <id> <word> --quote "<your words>"`, a CLI verb that stamps `RULED in-session <commit>` and commits with the quote in the body. This is the channel 17 of the last 21 rulings used. `Edit(decisions/owner_queue.md)` moves to **deny** for file tools so no agent authors a ruling through Edit.

**Channel B (secondary, unattended): edit and commit with the nonce.** The promoter applies a ruling only if (a) the file's last commit is not by the autopilot identity, (b) the commit body quotes the nonce from that week's report email, (c) the tree is clean at that path, (d) ids/hashes match. **Why the nonce and not git authorship:** 216/216 commits since 7/20 carry your name; 208 carry the trailer including every in-session ruling — a trailer heuristic would *refuse* your real channel and *accept* scripted machine commits. SSH-signed commits are not configured (`commit.gpgsign`/`gpg.format` unset) and an agent key is equally reachable by a session running as you. Residual: an agent with Gmail access could read the nonce — accepted, because that agent is already positioned to type your word; the weekly lists every applied ruling. **In an SMTP-outage week there is no nonce, so Channel B is dead for that week — in-session rulings only**; the report states it.

**Two options rejected:** *reply-email keywords* (inbound mail = observed content, a new reauth surface, reverses `notify.yaml`'s outbound-only posture) and *an uncommitted root `RULINGS` file* (no provenance; untracked dirt that stands the whole nightly layer down).

## 8. What stays deliberately manual, and why

- **Rulings with a recommendation** (forks, WOs, tier semantics, "third branch" trigger reads). Since 8/10 every answer was yes-to-rec or a rider; the three genuine overrides before that (7/22 container gate → the determinant-leg rule; 7/28 Compass §G/§H; 8/09 "when a rule can be a test") each rewrote a rule. The word costs five minutes; the override channel is the value.
- **`quality_flag` choices, unnamed prints, aggregates, cross-house conflicts, lexicon hits.** Judgment misses no parser sees (Velos Jasper ×5 instances, Oldendorff 37.5→37.0).
- **Image eyeball on uncorroborated OCR tenors.** The corroboration conjunct makes the eyeball rare, not gone.
- **Report-day extraction and its forks** (WC basis, HFS, JV netting, commitments on/off curve). 11 of 24 refreshes in the window carried a fork or an anomaly. The machine drafts and lands; it does not decide.
- **Outage-week price salvage.** Optional by choice: the machine reports tape age rather than fighting a dead network.
- **Weights (§13.3), the k-band constant, `TXN_PURE_PLAY_K_BAND` allowances, transaction-file `as_of` policy, the strip-origin roll, new classes, pin bands.** Calibration is owner-gated by rule; "wide spreads are features" depends on nobody tuning — and a pin band is never widened by the machine.
- **`main` push, launchd install, GitHub secrets, outward contacts, IBKR.** Recorded owner decisions.
- **Decision-log annotations and `PLAN.md`.** The D3 loophole stays closed by construction and by test; the one machine-readable exception (predicted band) carries human provenance.
- **Week-close doc audit.** The report replaces the *read*; the audit is a consistency sweep (40 fixes on 8/16) the report does not do.
- **An LLM with write authority.** The vehicle either does not exist (`claude` absent) or auto-approves ask-tier; the 2026-06-15 two-hour schema-retry hang is the failure mode with no heartbeat — hence the turn budgets and the `started`-without-`finished` flag.
