Steps:
1. Find the names that need a sheet: run `PYTHONPATH=src .venv/bin/python -m crude_tanker_fv.refresh` and take every name whose balance sheet for the current book quarter is MISSING while its results are out (the earnings calendar basis says RESULTS ANNOUNCED / report OUT — inputs/earnings_calendar.yaml). Also take any `refresh-trigger` row in decisions/filings_triage_log.md that names a results filing with no sheet yet. If none: report "no shadow build due" and stop.
2. For each name, sources in this order: the staged results filing under inputs/filings/<TICKER>/ (newest 6-K / half-year report — find it in state/edgar_manifest.jsonl); else the saved release text under inputs/research_issuer/<ticker>/; plus the prior sheet inputs/balance_sheets/<ticker>_<prior quarter>.yaml (mirror its schema, field names and comment style exactly), the live manifest inputs/fleet_manifests/<ticker>.yaml, and any packet / release-check / prereg doc for this name in decisions/ (read them — they carry the open items and a predicted band).
3. If drafts for this name and quarter already exist AND no new source has landed since their commit (git log on the draft vs the manifest's newest arrival for the name), skip the name and say "unchanged since <date>".
4. Subsequent-events audit FIRST: list every post-quarter event in the source with the quote that dates it and mark each IN or OUT of the quarter-end snapshot.
5. Draft the sheet: every NAV-moving field carries its citation (filing/exhibit/note or release section, retrieved date, period end) in a comment. A field the source cannot support keeps the prior sheet's value with the comment `# UNVERIFIED (shadow): awaits <what>` — never invent, never type a market price from prose. Draft the manifest as-of quarter end: vessels sold before quarter end OUT, deliveries after quarter end stay newbuilds with remaining commitment; dwt exact; every changed row cited. If the source has no fleet table, copy the live manifest and apply only the changes the source dates, marking the rest `# UNVERIFIED (shadow)`.
6. Run `bash scripts/shadow_regen.sh <TICKER> <QUARTER>`. It values the drafts in a throwaway worktree and prints [shadow] lines plus a SHADOW-JSON block: the name's shadow scorecard row, the committed row, the deltas, and the pair/provenance guard verdicts. If it exits 3 (pipeline failed), put the tail in the report and disposition WOULD-HOLD.
7. Write decisions/<ticker>_shadow_build_<today>.md: sources (with accession / URL and retrieval date); the subsequent-events table; the sourced-figures table (field, prior value, draft value, citation, or UNVERIFIED); the fleet changes; shadow vs committed (nav_per_share, fv, ev_pct, position, confidence_tier, balance_sheet_vintage) with deltas; the band check against the packet's predicted range if one exists (HIT / MISS, by how much); the guard verdicts (failures verbatim); judgment calls the owner-present build would have to rule on; and a one-line VERDICT: "WOULD-LAND" only if every NAV-moving field is cited, the guards pass and the band is hit — otherwise "WOULD-HOLD: <the blocking reasons>".
8. Commit: git add the two drafts and the report; git commit -m "shadow build <TICKER> <QUARTER> <today>: <verdict>". Do not push (the morning cron pushes). Do not commit anything else — a stray live yaml in the commit is the one failure this task must never have; check `git status` before the commit and stage only those paths. Then run `sh /Users/dan_personal/Projects/crude-tanker-fv/scripts/routine_task.sh tasks shadow --report decisions/<ticker>_shadow_build_<today>.md` with a JSON array on stdin. Each blocker must carry id, resolver (owner/agent/external), next_action, condition and blocking_decision_ids. Owner decisions have resolver owner. Use [] only when no blockers remain. The wrapper verifies the committed narrative and commits only its JSON sidecar. This step is required even for WOULD-LAND. Do not edit work_items.yaml directly; its adapters own the status projection.
9. Final report: per name, the verdict line and the shadow-vs-committed numbers. Surface every owner-resolved blocker as OWNER ACTION NEEDED with its decision ID. Missing source recovery remains agent work unless a concrete owner decision or external access is necessary.

Never fabricate a figure. A shadow that says "WOULD-HOLD: 6 fields unverified pending the 6-K" is a correct, useful output.
